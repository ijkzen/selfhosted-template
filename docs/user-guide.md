## 1. 快速上手

1. 启动服务（见 README 的「快速开始」）。
2. 首次访问任意页面会进入初始化页：设置用户名与密码（密码 6-128 位），可选界面语言与浏览器时区。提交后即完成建号并自动登录。
3. 初始化只能执行一次——系统检测到已有用户后会跳回登录页。之后请用登录页进入。

> 单用户模型：整个系统只有一个账号，没有角色与权限概念。忘记密码需要直接操作数据库。

## 2. 界面结构

- **左侧边栏**：分「主菜单」（首页、笔记）与「管理」（定时任务、设置）两组；可折叠。
- **顶栏**：侧栏折叠开关、页面刷新按钮、语言切换、主题切换、账号菜单（退出登录）。
- **页面刷新按钮**：语义是「页面刷新」——清空当前页面已取的数据并立即重新拉取（排除登录态与版本号这类布局级数据）。刷新期间按钮禁用并旋转。
- **语言切换**：立刻生效，并同步写入后端设置表；未自定义标题的内置定时任务会跟随切换标题与描述。
- **主题切换**：浅色 / 深色 / 跟随系统，选择保存在浏览器本地。
- **会话**：Cookie 会话固定 7 天过期，不做滑动续期；过期后任意请求会跳转登录页，登录成功后自动回到原页面。

## 3. 首页

模板自带的占位页（应用名 + 一行欢迎语）。新项目在此放自己的概览内容。

## 4. 笔记（示例域）

模板自带的示例 CRUD 域，演示「列表 + 新建 + 编辑 + 删除」的完整前后端骨架：

- 列表支持搜索与分页。
- 「新建」按钮打开表单（标题 + 内容），字段校验失败时错误提示落在对应输入框。
- 每行提供编辑与删除操作，删除前弹确认框。

新项目应当把它整体替换成自己的业务域，改动点见 README 的「用这个模板开新项目」。

## 5. 定时任务

### 5.1 任务列表

按「分组 + 名称」字母序展示，选中某一行查看右侧（窄屏为下方）详情。列表项显示启停开关，可直接切换；停用的任务不会自动触发，但仍可手动执行。

### 5.2 新建与编辑

- **名称**：任务的唯一标识，需与后端注册的 handler 名一致。
- **标题 / 描述**：展示用文案（标题会跟随语言切换，除非你手动改过）。
- **表达式**：标准 Cron（5 或 6 段）或 `@every 1h` 这类间隔写法，另支持 `@hourly` / `@daily` / `@weekly` / `@monthly` / `@yearly`。表达式非法时提交会被拒绝。
- **分组**：仅用于列表归类。
- 编辑时**只有表达式变化才会重算「下次运行」**；只改标题或启停不会挪动计划。

### 5.3 详情与操作

详情区展示表达式、分组、上次运行、下次运行、说明，并提供：

- **立即执行**：不等下次计划，立刻跑一次（与计划触发走同一条通道）。
- **编辑 / 删除**：删除为软删除，任务不再出现在列表中。
- **查看日志**：打开日志弹窗。

### 5.4 执行日志弹窗

- 上半区是**实时日志**：任务正在执行时逐条推送；任务结束后保留本次输出并显示结束状态与耗时。
- 日志条目按 seq 排序去重，断线后自动重连（指数退避，最多 5 次）；重连失败会提示手动刷新页面。
- 接收端积压导致事件丢失时，后端会发 `reset` 信号，前端重新拉取该次执行的全量日志并按 seq 合并（不会覆盖掉期间新到的日志）。
- 自动跟随底部滚动；向上滚动会暂停跟随，出现「回到底部」按钮。
- 下半区是**历史执行**列表，点选某次执行可查看其完整日志。

### 5.5 保留策略

每次执行最多保留 2000 条日志（超出丢弃并标记截断）；每个任务只保留最近 30 次执行，更早的执行连同日志一并清理；卡死超过 6 小时仍处于「运行中」的执行会被自动标记为失败。

## 6. 设置与账号

### 6.1 设置项

设置表为键值结构，带类型（String / Int / Float / Bool），列表显示键、值、类型与更新时间，支持编辑与删除。模板内置两项：

| 键 | 说明 |
|------|------|
| `language` | 界面语言（`zh-CN` / `en`）。修改后立即生效并同步前端。 |
| `timezone` | 定时任务的 cron 语义时区（IANA 名称，如 `Asia/Shanghai`）。修改会重建全部定时任务并重算下次运行时间。 |

`language` 与 `timezone` 是系统内置键，**不可删除**（删除会与进程内缓存分叉）；其余自定义键可删除。

### 6.2 账号

账号菜单提供「修改密码」与「退出登录」。修改密码需要验证旧密码；成功后除当前会话外的其他会话全部失效。

### 6.3 消息通知（飞书）

设置页右上角「消息通知」打开配置弹窗。当前只支持飞书一个渠道，用于在**定时任务执行失败**时推送消息。

配置有两条路径：

- **手填**：填 App ID 与 App Secret，选择接收者类型（`open_id` 或邮箱）并填接收者。
- **扫码创建**：点「扫码创建」，用飞书客户端扫描弹出的二维码，在自有租户内一键创建自建应用；成功后凭据自动回填表单，**仍需点保存**才会落库。

其它行为：

- **测试发送**用表单当前值真实发一条消息，不落库配置——可以先验证再保存。
- **编辑时 App Secret 留空表示不修改**，后端沿用库中原值；首次创建必须提供。
- 弹窗底部的**总开关**控制自动通知是否发送，关掉后任务失败不再推送（手动「测试发送」不受影响）。
- 面板会显示**上次发送时间**，失败时改为显示失败原因（如「飞书应用缺少发送消息权限」）。

App Secret 整段加密落库（`SECRET_KEY` 未设置时明文存储并打 warn），接口只回显掩码（前 3 位 + 后 4 位）。

## 7. 自动化行为

- **启动时**：建表并执行增量迁移；把上次进程中断留下的「运行中」执行标记为失败；清理无归属的孤儿日志；幂等写入内置任务与设置种子行。
- **运行中**：定时任务按各自表达式触发；执行日志实时推送到打开的日志弹窗；任务执行失败时（若通知渠道已配置并启用）推送一条含任务名与失败原因的飞书消息；日志目录每天清理一次超过 30 天的文件。
- **关闭时**：先停止接收新连接（长连接最多等 8 秒收尾），再停止调度新任务并等待在飞任务结束（最多 10 秒），最后退出。

## 8. 术语速查

| 术语 | 含义 |
|------|------|
| 初始化 | 首次启动创建首个用户与默认设置的流程 |
| 会话 | 服务端 Cookie 会话，令牌哈希入库，固定 7 天过期 |
| 定时任务 | 可管理的 cron 配置（表达式、时区语义、启停） |
| 任务执行 | 定时任务的一次运行记录（状态、耗时、日志） |
| 任务日志 | 按执行组织的日志流，实时经 SSE 推送，历史定期清理 |
| 设置 | 键值配置项，带类型枚举 |
| 通知渠道 | 出站告警的配置载体（当前仅飞书），凭据加密落库、总开关与发送结果 |
| 扫码创建 | 用飞书客户端扫码一键创建自建应用的授权流程，凭据回填后由用户确认保存 |
| 笔记 | 模板自带的示例业务域 |
